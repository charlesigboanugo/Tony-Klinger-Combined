# Tony Klinger — Architecture Notes

Canonical, version-controlled architecture for `tonyklinger.com`.

These documents are the **source of truth** for the system's structure. Code follows
the architecture; when code and architecture diverge, one of the two is wrong and the
divergence must be resolved explicitly — never left silent.

## Maintenance Rule

Architecture documents are updated **as part of the change that affects them**, not
afterwards and not on request. Any of the following requires the relevant document to
be amended in the same piece of work:

- A new or renamed route, application area, or workspace
- A new product type, membership tier, or entitlement rule
- A change to the payment → order → entitlement → access/booking chain
- A new or changed external service, integration, or webhook
- A new background/scheduled process
- A new database entity or a change to an existing entity's role in the model
- A change to authorization, roles, or RLS policy shape
- A change to the design-system, theming, or navigation model
- Any deliberate deviation from a stated rule in these documents

Purely local implementation detail (component internals, styling tweaks, refactors that
preserve the model) does **not** require an architecture update.

When a document is amended, record the change in the Change Log below.
